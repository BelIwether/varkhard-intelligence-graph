# VARKHARD Intelligence Graph

VARKHARD Intelligence Graph traces AI agent access and explains security findings with evidence from an embedded Relate graph.

## Use case

Security reviewers can see which agent acted on a resource, which permissions applied, and how one interaction led to another. The demo models five fictional agents and four fictional resources, including an external outbox represented by a graph node.

## Run the dashboard

From the repository root, use Python 3.10 or later and Node.js 20.19+ on the 20.x line or 22.12+. The demo runs locally without a database server or credentials.

```sh
python -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[test]'
npm ci --prefix frontend
npm run build --prefix frontend
python -m uvicorn varkhard.api:app --host 127.0.0.1 --port 8010
```

Open [the dashboard](http://127.0.0.1:8010/) or [the API documentation](http://127.0.0.1:8010/docs). FastAPI serves the built React application and reads the bundled `examples/synthetic-demo.rl` snapshot. Set `VARKHARD_DB_PATH=/path/to/graph.rl` before starting Uvicorn to use another Single File populated with the VARKHARD schema.

For frontend development, keep the API running on port `8010`, run `npm run dev --prefix frontend` in another terminal, and open [the Vite dev server](http://localhost:5173/). Vite proxies `/api` to FastAPI. Set `VARKHARD_API_URL` for the Vite process if you use a different API address.

## Dashboard walkthrough

1. Open the graph to see the five fictional AI agents and their resources, permissions, and actions. Pan the canvas, zoom with the graph controls, and drag a node to reposition it. Use **Fit View** to return to the overview.
2. Select **Preview Agent** from the agent picker or the graph. The inspector shows its grants, baseline permissions, and recorded actions, including the denied catalog write.
3. Select **Unauthorized Access**, **Excessive Permission**, and **Suspicious Chain** under **Security findings**. Each finding highlights its evidence in the graph. Inspect the event, grant, or handoff chain and read the explanation generated by the detection rules.

## CLI and tests

The CLI opens the bundled snapshot in read-only mode and prints the three findings as JSON. You can also recreate the graph at the default CLI path.

```sh
python -m varkhard --db examples/synthetic-demo.rl analyze
python -m varkhard seed
python -m varkhard analyze
python -m pytest -q
npm run build --prefix frontend
```

`seed` creates `data/varkhard-graph.rl` and writes the synthetic fixtures. Repeating it with the same data leaves the graph unchanged. Use `--db PATH` before the command to select another `.rl` file.

## Dashboard API

| Route | Response |
| --- | --- |
| `GET /api/graph` | Agents, resources, permissions, interactions, graph nodes and edges, findings, and snapshot filename. |
| `GET /api/agents` | AI agent records. |
| `GET /api/resources` | Resource records with classification and boundary. |
| `GET /api/findings` | Findings with rule explanations, evidence, and the IDs used to highlight the graph. |

Each API request opens its own read-only connection, queries the file, and closes the connection on the same worker thread. If a writer has locked the file or the file is unavailable, the API returns HTTP `503`. Close the writer or correct the file path and retry in the dashboard.

## Findings

Every finding includes a rule ID, an explanation, and evidence from the graph. Timestamps in the evidence use ISO 8601 UTC. The seeded demo produces one finding for each rule.

| Rule | What it checks | Demo evidence |
| --- | --- | --- |
| `unauthorized_access` | An observed interaction has no current grant matching its agent, resource, and action. A denied event records an attempt. | `interaction-catalog-write-denied` records a write attempt from the Preview Agent, whose grant covers reading the catalog. |
| `excessive_permission` | A grant has no matching entry in the approved least-privilege baseline. An unused grant can be valid when the baseline approves it. | `grant-archive-delete` allows the Maintenance Agent to delete from an archive whose baseline allows only read and write. |
| `suspicious_chain` | Linked successful interactions show an agent reading a restricted resource, handing it off to another agent, and that recipient exporting to an external resource. The three event timestamps must strictly increase and span at most 600 seconds. | `interaction-ledger-read` → `interaction-ledger-handoff` → `interaction-outbox-export`. The related actions occur within 180 seconds and are individually granted. |

The MVP evaluates interactions against the grants currently stored in the file. Assessing a historical event against the policy in effect at the time would require permission history. Treat the baseline as complete when interpreting excess grants. The chain rule uses explicit event links and reports a pattern for review based on event metadata.

## How it uses Relate

The Python core uses embedded Relate Single File via `relate-db==1.2.0`. Single File lets independent CLI processes share a persistent graph through one portable file. The default path is `data/varkhard-graph.rl`. Parameterized Cypher writes graph records and reads permission scopes, event targets, and explicit handoff paths.

```text
(AIAgent)-[:HAS_PERMISSION]->(Permission)-[:ON_RESOURCE]->(Resource)
(AIAgent)-[:PERFORMED]->(Interaction)-[:TARGETS]->(Resource)
(Interaction)-[:HANDED_TO]->(AIAgent)
(Interaction)-[:TRIGGERS]->(Interaction)
```

Grant and baseline records are both `Permission` nodes, each tagged with its kind. The two interaction relationships represent the recipient of a handoff and explicit links from parent events to child events. The interaction model stores `occurred_at` as Unix seconds. Detection traverses these relationships to find the agent, resource scope, and ordered chain behind each explanation.

Relate locks the Single File while a writer has it open. Wait for the writer to close before opening the same file for analysis. Analysis uses `read_only=True` on an existing file. Multiple read-only connections can coexist, and a writer can reopen the file once the readers close. Each ingest commits a batch and calls `flush()` to checkpoint the committed data. When embedding `GraphStore` in Python, open it, perform queries or writes, and close it on the same thread. Use its context manager to release the connection promptly.

The automated tests use temporary Relate files and exercise persistence after closing and reopening the database. See the [Relate Python API reference](https://relatedb.ai/docs/reference/api/python/).

## Project structure

| Path | Purpose |
| --- | --- |
| `examples/synthetic-demo.rl` | Checked-in snapshot containing only the fictional demo records. |
| `data/varkhard-graph.rl` | Local Single File generated by `python -m varkhard seed`. Git ignores this file. |
| `varkhard/demo.py` | Source for the agents, resources, permissions, and events in both demo stores. |
| `varkhard/store.py`, `varkhard/models.py`, `varkhard/detection.py` | Relate storage, graph records, and security detection rules. |
| `varkhard/api.py`, `varkhard/dashboard.py` | FastAPI routes and JSON projection of the graph and findings. |
| `frontend/` | React and TypeScript dashboard, graph visualization, and Vite build. |
| `tests/` | Storage, detection, CLI, and API tests. |

Inspect the snapshot's event links directly with the embedded Relate API.

```sh
python - <<'PY'
import relate

with relate.connect("examples/synthetic-demo.rl", read_only=True) as graph:
    print(graph.execute("""
        MATCH (parent:Interaction)-[:TRIGGERS]->(child:Interaction)
        RETURN parent.id AS parent_id, child.id AS child_id
        ORDER BY parent_id, child_id
    """).data())
PY
```

## Dependencies and AI disclosure

The backend uses Python, FastAPI, Uvicorn, and Relate. The frontend uses React, TypeScript, React Flow, and Vite. The Python tests use pytest and HTTPX. OpenAI Codex assisted with implementation, documentation, and verification. At runtime, deterministic rules generate the findings from the graph.
